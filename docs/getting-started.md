# 第一次用「视频制作」

这份指南用一支课程宣传片走一遍。你可以照着发每一步的话，也可以把目标、规格和素材一次说完。已经确认的信息会带到后面。

## 1. 怎样安装并开始

可以让 Agent 协助安装，也可以在 GitHub 点 **Code → Download ZIP**，解压后把文件夹改名为 `video-workflow-guide`。保留整个文件夹，并确认打开它就能看到 `SKILL.md`。下表列的是把 Skill 装到当前项目的方法。

| 你用的客户端 | 把文件夹放到项目的哪里 | 怎样开始 |
| --- | --- | --- |
| [Codex](https://developers.openai.com/codex/skills) | `.agents/skills/video-workflow-guide/` | 输入 `$video-workflow-guide`，再描述想做的视频 |
| [Claude Code](https://code.claude.com/docs/en/skills#choose-where-skills-load) | `.claude/skills/video-workflow-guide/` | 输入 `/video-workflow-guide`，再描述想做的视频 |
| [Cursor](https://cursor.com/docs/skills#skill-directories) | `.agents/skills/video-workflow-guide/` | 在 Agent 对话里输入 `/`，选中 Skill 后描述需求 |
| [VS Code 的 GitHub Copilot](https://code.visualstudio.com/docs/agent-customization/agent-skills) | `.github/skills/video-workflow-guide/` | 在聊天框输入 `/video-workflow-guide`，再描述需求 |

在你放入 Skill 的项目目录开启新会话。也可以直接用一句话描述需求，例如：

```text
用 video-workflow-guide 帮我做一支课程宣传片。观众是第一次接触机械臂的人，希望他们看完知道这门课会带着练哪些操作。
```

`video-workflow-guide` 是安装和调用时使用的名字。已经装过的用户可以更新原来的 Skill。如果还装着旧的「剪映口播与教程视频剪辑」，「视频制作」也能承接精剪和剪映草稿交付。

不同客户端可以沿用项目规划、素材整理和分镜流程。实际制作、播放预览、渲染导出及剪映交接，按你的任务检查当前环境能调用哪些工具。[按需安装入口](../references/install-on-demand.md)

## 2. 跟着对话走四步

### 第一步 · 说目的

说清楚给谁看、想让对方看完做什么。一句话就够。

> 给刚开始做硬件的人看，让他们了解这门课会教哪些真机操作，愿意去试听。

Agent会区分宣传片和操作教程。宣传片用一个能看懂的例子说明课程价值。教程会把按哪个按钮、发生什么和怎样判断成功讲清楚。

### 第二步 · 定规格

你可以直接说横版或竖版、时长、中文或英文、想保留哪些声音。如果不确定，先说打算发在哪里，让Agent给建议。

> 16:9 横版，中文，约 1 分钟。保留现场操作声，关键动作可以配音效。我没有指定字体，请先给可商用的候选。

画幅就是视频宽高的比例。横版可以选 16:9 或 4:3，竖版可以选 9:16 或 3:4。需要多个画幅时，直接说「16:9 和 3:4」这样的具体比例。通常先确认一个画幅的样段，再按其他画幅重新排版。

### 第三步 · 给你手头有的素材

| 手头有什么 | 发来时可以加一句 |
| --- | --- |
| 课程网页、产品链接、讲稿或几行笔记 | 「第二段是最重要的内容。」 |
| 录屏、实拍、口播原视频 | 「这段要保留操作顺序，夹爪成功夹住是重点。」 |
| SRT 字幕 | 「这是这条原视频的字幕，原声要保留。」 |
| 标志、品牌字体或音乐 | 「这几项是我指定要用的。」 |
| 已有剪映草稿 | 「我用剪映专业版桌面端，先在副本上修改。」 |

有多少就先发多少，文件名保留原样即可。Agent会给一份短清单，说清哪些能用、哪些建议处理、还缺哪段。比如缺少结果画面，它可能请你补一段「从点保存到出现保存成功的连续录屏」。

Agent会在工作副本里统一命名，方便你们说的是同一段素材。比如把 `Screen Recording 001.mov` 整理为 `01-02-开始采集-录屏.mov`。有实拍时会先检查是否需要防抖、重新取景。口播会先检查口误、长停顿和噪音，再按你希望保留的原声处理。你上传音乐时，Agent会从曲子里找适合亮相、换段和收尾的时刻。

### 第四步 · 选你想先看什么

| 选项 | 你会看到什么 | 你可以怎么回 |
| --- | --- | --- |
| 静态视觉参考 | 同一素材的几张画面设计，比较字、颜色、构图和实拍占比 | 「整体用 A，真机画面用 C 的近景。」 |
| 分镜 | 一张按顺序写清镜头、文字、动作和声音的简表 | 「先给结果，再讲怎么做。」 |
| 动态样段 | 取最有代表性的几秒或一小段实际播放，按约定带原声、音乐或音效 | 「0:12 字出来太快，留一拍让我读完。」 |
| 第一版 | 方向和规格已经清楚时，按约定先做一版供你看 | 「先做完整一版，导出前给我确认。」 |

第一次做可以从静态参考开始。选好画面方向，再核对分镜里的顺序和重点。你说「照这个做样段」，Agent就会制作，并先检查标题能否读清、镜头衔接和声音，再把可播放版本发给你。已经定过的规格和风格可以直接沿用。

## 3. 看片时怎样提意见

说**哪里、看到什么、希望怎么改**就足够。你可以用时间点，也可以用截图画框。

- 「0:07 机械臂型号太小，放大一点，靠近设备。」
- 「从‘模型保存’到夹爪那一下像翻页，看看能不能用真机动作把两段接起来。」
- 「原声有点被鼓点盖住，把音乐压一点。」

样段通过时，可以直接划定下一步。

```text
这个样段的风格和节奏可以。请按这个做完整横版，先给我看全片，再确认导出。
```

如果没打算做整条片，可以说「只交这个样段」。想修已有素材时，也可以直接说「只剪掉 0:23 那句口误」或「只改第二章字幕」，Agent会从该剪辑任务开始。

## 拿到成片或剪映草稿后怎么检查

- **拿到 MP4**：用你准备发布的平台或常用播放器试听，检查画幅、语言、字幕和声音。先看片头、关键操作和片尾，再正常速度从头看一遍。
- **拿到可编辑剪映草稿**：在接收工程的实际设备和对应客户端打开，确认素材能找到、字幕能改、声音能单独调。如果会交给同事，提前说对方用的是 Windows、macOS 还是网页端，请Agent把需要的素材、打开方法和可编辑范围一起交付。
- **已经有草稿需要续剪**：把最新草稿位置和要改的范围告诉Agent。比如「只改第二章字幕，用副本，保留其他轨道和原声」。先看有改动的片段，再决定是否需要导出整条。

如果你只要成片，可以在开头说「只要 MP4」。如果有后续改字、替换画面或调声音的需要，说明你用的剪映版本和设备，便于从制作时就保留相应的可编辑内容。[原生草稿验收](../references/jianying-draft.md)

## 常见问题

**我只有一个链接或者一句想法。** 先发给Agent，就能开始确定目标和方向。需要展示真实操作的部分，Agent会指出还缺哪一段真实素材。

**我没有音乐。** 可以指定保留原声、以旁白为主、只配动作音效，或先试无配乐样段。有合适的音乐以后，再上传并说清想怎么用。

**它说缺工具，我需要都装吗？** 请它说清「本次缺哪一个、缺了哪一步做不了、哪些事还能先做」。只处理当前需要的依赖。[按需安装入口](../references/install-on-demand.md)

**我找不到 `video-workflow-guide`。** 先对照上表检查文件夹位置。确认 `SKILL.md` 就在 `video-workflow-guide` 文件夹里，然后从同一个项目目录开启新会话再试。

**工程能打开，但是字幕或素材改不了。** 指定你想改的内容，让Agent在目标客户端演示实际编辑，并说明哪些是渲染后的效果层、需要在哪里回源修改。[交付验收](../references/delivery-qa.md)
