# 口播、教程与剪映精剪

适用于已有录制素材、剪辑时间线或明确剪辑任务的用户。沿用已确认的素材、画幅、语言、字体、声音和交付规格。根据当前任务补问缺失的信息，从就绪的阶段开始。用户从想法开始，或希望依次看视觉、分镜和样段时，切回[新片制作流程](workflow-guide.md)并带入已有决定。

## 先确定剪辑范围和主工程

| 当前任务 | 从哪里开始 |
| --- | --- |
| 已有口播或 Q&A，明确要精剪 | 核对原视频、原声和现有字幕。按问题与回答或语义段落标出可剪的口误、重复和空白。 |
| 已有软件、硬件或课程录屏，明确要剪成教程 | 从真实录屏和实拍确认操作入口、动作与结果，再做剪辑顺序和必要的解释画面。 |
| 已有剪映草稿，只改某段、字幕或声音 | 核对实际目标客户端、最新草稿及对应范围，另存后直接修改。 |
| 从素材开始，明确需要可编辑剪映项目 | 从第一段就规划能在剪映改的文字、素材、字幕、关键帧和音轨。先做代表性小样并在目标客户端验证，再扩展。 |

只修字幕、音频、剪点或某段画面时，复用当前主工程、已确认内容和其他相关约束，从验收该项所需的最小预览开始。已有草稿按实际客户端区分剪映专业版本地草稿、CapCut 网页项目或 STDraft，继续使用已工作的入口。[原生草稿与分层验收](jianying-draft.md)

## 根据实际录制内容剪辑

- **口播与 Q&A**。先完整听原声并核对 SRT，按真实语义划分问答、观点和例证。字幕与原声有差异时以听到的内容为准。按用户授权剪除口误、重复或多余停顿，保留信息顺序、语气和必要的思考停顿。用真实问题或明确标为摘要的问句，配图和 B-roll 要能解释对应语句。
- **录屏与实拍教程**。逐步核对入口、动作、参数、等待和结果。保留源入出点、鼠标或手的操作位置，并给读数、按键和成功状态足够时间。可以压缩可省略的等待，必要时标明加速。脚本和实录冲突时给出具体时间码，缺少的关键动作或结果需要补录，示意需标清身份。
- **混剪**。用同一时间线对齐人物讲解、录屏和实拍。口播驱动的关键词、图解和人物包装可交给 Agent Motion。网页、产品细节、操作解释或确需 B-roll 的镜头可交给 video-shotcraft。只有录音时，可做语义图解和素材配合。用户指定的工具及已有可编辑工程优先。[分流、预览与交接](routing-and-preview.md)
- **字幕与声音**。按真实剪点把源字幕统一映射到成片时间，处理变速和跨镜，再按成片时钟检查。对白、环境声、音乐与音效按需独立。新增动作音效和用户上传的配乐沿用[统一声音流程](motion-and-sound.md)。

## 根据任务预览与交付

全新包装仍可用本片真实素材确认风格，再看片段。方向明确或局部修改时，直接展示改动区域及前后镜头。涉及读数、字幕密集处或动作衔接时，用包含该难点的片段自审后再交用户观看。沿用已有确认，按阶段记录反馈。[风格选择、确认记录与自审](workflow-guide.md)

**需要可编辑剪映工程时**，分别交接原片和源入出点、原生文字与关键帧、必要的独立图形层和音轨。按任务需要组织章节。复杂动效可用独立预渲染层并保留可重渲染的源和替换方法。按目标版本实际测试打开工程、改字、裁原片、隐藏包装、移动关键帧、独奏音轨及章节进出。其中与交付无关的检查按实际范围取舍。[原生组件与版本边界](component-contracts.md)

已有工程的局部精剪，保留其他轨道及编辑关系，核对修改区间、相邻剪点和回放。成片、可编辑草稿和源工程分别按约定交付。说明目标客户端和实际执行的验收，分开报告文件检查、原生编辑实测与连续播放结果。[交付验收](delivery-qa.md)
