# 分流、预览与交接

## 按项目选择主工具

先采用用户指定的可用工具，或继续已有可编辑工程。新项目通常选一个主工具，其他工具按镜头或声音职责加入。两种工具都适合时，由用户希望怎样看预览、迭代和接手工程来决定。工具选择和交付格式分开记录。

| 工具 | 优先使用的情形 | 交回主项目的内容 |
| --- | --- | --- |
| OpenMotion | 从零开始，用户希望边看预览边改。或已有 OpenMotion 工程。 | 可播放预览、项目版本与可继续调整的场景。 |
| video-shotcraft | 已有 Remotion 工程，指定 Shotcraft 镜头卡，或团队需要维护镜头源码。可承接网页、产品、录屏及指定 B-roll。 | 镜头预览、配方及可复用工程或渲染件。 |
| Agent Motion | 画面由口播语义驱动，如关键词、讲解图示和真人段落。只有录音时可制作纯动画语义包装。 | 语义锚点、动效预览及分配镜头的素材。 |

仅需修字幕、精剪、改声音或编辑现有草稿时，直接进入 [口播、教程与剪映精剪](editing-workflow.md)，调用足够完成本次工作的流程。实拍或录屏已把关键操作讲清楚时，按实际需要补动效。为真实口播保留内容次序和原声，剪改遵守用户授权。教程从真实的操作入口、动作和结果组织画面。仅配音的段落沿用其音频与画面需求。

## 读取实际工具入口

- **OpenMotion**。先用会话已提供的 Skill 和连接。原创走导演工作流，现有工程局部修改走对应制作入口。需要模板建议时核对实际模板或示例。保存可编辑项目，预览和导出绑定实际项目版本。
- **video-shotcraft**。读当前安装版本的 `SKILL.md`，局部镜头按单镜头入口，完整宣传片按上游工作流采用已确认的模板、自主或共同创作模式。已有授权随任务传递。在约定路径中有影响制作结果的选择时才向用户确认。[video-shotcraft 接入与交接](shotcraft-handoff.md)
- **Agent Motion**。读实际 checkout 的 `AGENTS.md` 和对应 Skill。口播、SRT 或参考音频按该版本所需入口做语义分析，再制作已分配镜头。[Agent Motion 接入与交接](agent-motion-handoff.md)

记录可核实的入口、版本和适用授权。缺少本次所需能力时先说明受影响的操作，并给可用路径。先推进能独立完成的素材整理、静态参考或分镜。安装方法见 [按需安装入口](install-on-demand.md)。

## 预览实际产物

按用户选的预览阶段推进。静态视觉参考优先用同一段真实素材、同一目标画幅和接近最终长度的文字，做 2–3 张可比较的整体方向。至少展示能说明视频实际内容的画面，必要时补代表性的开场或信息密集帧。输出并展示 PNG/JPEG，检查关键字、行距、对比度、裁切和安全区。用页面真实截图或录屏解释软件操作。

用户想比较动效，或已明确需要 Shotcraft 镜头配方时，核对真实的卡名、变体、配方与实际 demo，附可查看的样片入口。说明它帮助观众看懂什么，以及交付时在哪里改。选择静态视觉方向的用户先看视觉图。静态样张确认视觉，动态样段另看运动、阅读时间和声音。

## 共用交接数据

用 [handoff.json](../templates/handoff.json) 的结构按项目填写。主工程持有全片时间线和唯一的最终字幕及混音。共享画幅、帧率、字体、项目色彩、镜头归属与交付范围。对每个任务保留源素材和源入出点、成片起止帧、变速映射、动画触发点、声音用途，以及源工程和可编辑范围。跨工具用零基整数帧与区间 `[in, out)`，字幕映射到成片时钟后统一贴帧。

各工具只制作分配的片段。中间预览的参考混音单独标记，主时间线只使用确认的一套音轨。交付目标是剪映草稿时才走剪映原生转换和目标客户端验收。需要动作音效时把事件交给 [sound-effects](motion-and-sound.md#动作音效)。
