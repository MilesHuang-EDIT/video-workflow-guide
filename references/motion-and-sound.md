# 字幕、音乐与声音

## 按语义设计动效

| 触发点 | 可以做 | 留意 |
| --- | --- | --- |
| 提问起句 | 问题卡、编号、评论引用 | 未提供原评论时做问题摘要卡，保留真实语义 |
| 关键词或数字落点 | 原生文字强调、短弹入或数字切换 | 同时只突出当前要看的信息，避免重复字幕 |
| 举例或界面操作 | 图解、实拍插入、箭头和局部放大 | 用真实操作对位，露出鼠标、读数和成功状态 |
| 章节切换、结论 | 标题页、复盘卡或简洁状态变化 | 留可读的停留时间，不盖住紧邻的句子 |

从一小段确定字体、色彩、留白、字幕安全区、缓动和音色。先验证信息最密的画面以及竖屏按钮区，检查字幕与脸、手和操作区域的冲突。中英文混排遵守当前项目的字体要求；缺字、替换字体或换行变化，以客户端实际预览为准。教程字幕和标注必要时挪位置，避免挡住点击目标。动效应服务重点，常规口播句子允许只留字幕。

## 声音

- 有人声时先对齐画面和原声。剪映若独立编辑了抽出的原声，把视频素材的音量归零，避免同一人声叠放；补录、环境声与设备声按实际用途分别保留。
- 仅在声音需求允许时加入配乐或音效。音效按信息出现、实际点击、状态反馈或转场落帧；人声开始前后留空间，避免音效遮住辅音。音乐按口播动态调整，保留可单独调节的音轨。声音源可替换，保留素材来源。
- 输出静音时核对用户是否要求无音轨或仅没有可闻声音。保留声音时，试听对白与包装最密处和首尾；测量参数遵守发布规格或项目要求。

## 用户上传音乐后的自动分析

**触发条件**　用户把音乐作为本片素材上传，且本片会使用配乐。默认用户只需要上传文件。向导直接分析，四步问卷沿用既有内容。BPM、音乐段落、重音与收尾时间由后台确定。用户主动提供的标记可以作为剪辑锚点，先核对它指的是哪份音轨及其时间格式。用户已选择静音或只保留原声时，以该声音设置为准。v0.6 的音乐分析只处理用户上传的配乐。项目无配乐时，按约定保留原声、旁白、动作音效或静音。

1. **先识别全曲段落。** 读取原始音频或视频中的音乐轨。结合波形、短时能量和低、中、高频的变化，识别前奏、进入主段、递进、留白、乐句边界以及节奏结束后的尾音。分别记录最后一个适合落画面的声音事件与音频文件实际结束的位置。
2. **再标节拍与重音。** 节奏稳定时估算 BPM 和拍点，用实际底鼓和其他明显击打的起音校正。区分普通拍点、适合换章的乐句边界、能量实质变化和适合落标题的收尾重音。拍点不稳定或音乐以氛围为主时，跟随乐句、停顿和明显的声音事件安排。低置信度的点先当候选，到样段里核对。
3. **把音乐时间换算成视频时间。** 结合分镜决定采用的乐句、进出点和关键动作。按需从完整乐句或自然停顿处剪接，检查接缝与尾音。保留原始音频和配乐剪接映射。记录「源音频时间 → 当前时间线时间／帧 → 声音事件 → 对应画面」。音乐裁剪、起点移动或重剪后，重新换算受影响的片段。
4. **按内容分配动作。** 把最清晰的重音留给亮相、结果揭示、换章或片尾，让动作提前起势，在重音处接触、落定或完整显露。普通拍点可以配局部动作或留给画面停稳。给字幕、教程操作、口播与结果画面足够的观看时间。画面工具接收时间点与动作意图。需要动作音效时，把同一份时间线中的相关事件交给 sound-effects。
5. **用动态样段验证。** 选一段能体现本片节奏的内容，直接放入用户上传的音乐，至少覆盖一个有代表性的画面变化。样段如果包含片尾，一并检查最后的重音与标题停留。送审前以正常速度开声音连播，检查动作落点、剪接、尾音、人声与原声的清晰度，再回到疑点核对关键帧和音频事件。用户只看原来的样段，可以说「这里有点赶」或「希望亮相更有冲击力」。向导把这类反馈转成调整，重渲染并复看。

**配乐映射示例。** 机械臂课程宣传片使用的《Super Ballin》原始 WAV 约 58.87 秒，约 106 BPM。约 27.16 秒是可换章的乐句边界，约 54.37 秒是收尾重音。剪到 27.5 秒的样段后，换章约落在 15.9 秒，片尾标题约落在 25.0 秒。每次更换音源或调整剪辑点后重新映射。

## 动作音效

**调用工具**　使用 [Barty-Bart / motion-graphics / sound-effects](https://github.com/Barty-Bart/motion-graphics/blob/main/skills/sound-effects/README.md)。这是三个画面工具共用的音效步骤。用户要求只保留原声或静音时，按其声音选择处理。用户看到的仍是已有的样段、成片和反馈流程。

1. **画面工具交接动作时间。** 从当前时间线优先取动作点，注明全片时间或样段时间、帧率、动作类型、先后关系、重要程度，再交给 sound-effects 形成音效点表（`cues.json`）。点击、物体接触、结果确认和重点揭示分别记录。口播、现场原声和已确认配乐保持可独立引用。
2. **样段先听关键动作。** 需要音效的样段用同一 Skill 处理，挑和动作材质匹配的音效，按画面完成帧或声音峰值对齐。每个已选发声动作先确定一处清楚的反馈，给周围的静音、人声和原声留空间。使用上传的配乐时，沿用上一节生成的音乐事件和时间线映射。向导向画面工具交回可调整的重音位置，保护已确认的剪辑、音乐结构和原始操作时序。
3. **按项目处理原声和配乐。** 上游一键脚本需要配乐参数，输出时重新封装自己的混音。全片含口播或现场原声时，保留独立底轨，使用 sound-effects 的点表、素材、摆位和检查流程，再在主工程合流。只要音效时，沿用同一 Skill 的选音、对齐和检查规则，在主工程合成所需音轨。可编辑交付时保留经许可的音效素材与摆位记录。上游用法与实现见 [SKILL.md](https://github.com/Barty-Bart/motion-graphics/blob/main/skills/sound-effects/SKILL.md) 和 [sound_pass.py](https://github.com/Barty-Bart/motion-graphics/blob/main/skills/sound-effects/scripts/sound_pass.py)。
4. **全片定稿前复核最终混音。** 按实际导出文件检查关键动作的声画落点、人声清晰度、响度、真峰值和单声道兼容。交付规格已明确时按该规格验收。保留上游生成的音效报告、来源和版权记录，供向导做检查和局部返修。优先用内置素材库，额外素材按实际发布用途检查使用范围。报告留在后台，需要用户判断或影响交付的问题在正常预览反馈里提出。

制作工具已有的音效先核对，确认沿用的声音可作为输入。时间线变动后重新同步相关声音。缺少 sound-effects 时可继续画面工作，并在预览注明待配的范围。
